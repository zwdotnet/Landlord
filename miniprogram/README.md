# Landlord 租务小程序

原生微信小程序，无客户端npm依赖。租客保留微信登录、首次填写入住手机号、等待房东关联、本人房屋/资料、账单分页与明细、逐笔实收/冲销、合同原件及PDF/图片查看，以及原有四个底部入口。房东支持现有账号密码登录、审核分流、轻量工作台、台账切换、房源/账单查询、微信绑定/解绑及快捷登录、抄表录入与保存回查。本地已增加服务端账单预览/明确确认出账、整笔线下实收与逐笔归档收据。房东使用普通页面、共用台账和模块权限；费用调整、退租结算、按项目分摊及冲销继续使用Web。

启动页为`pages/entry/index`，恢复会话时读取服务端身份；房东审核状态另由`/rental/users/me/approval`核实，因为当前`/auth/me`没有status。平台管理员只访问本人或获授权的业务台账，不提供小程序平台管理控制台。客户端尚未上传或发布；最新本地自验和证据见根目录STATE.md及测试报告§14—16。

## 配置与打开

在项目根目录 `.env` 配置 `WX_APP_ID` 和 `WX_APP_SECRET`。小程序仅取得 AppID；`wx.login` 的一次性 code 交给服务端 `/auth/wechat/login`，房东绑定及快捷登录分别调用 `/auth/wechat/bind` 和 `/auth/wechat/landlord-login`，均由服务端调用 `code2Session`。AppSecret 和 session_key 不进入小程序，OpenID 不作为客户端凭据返回。

本机 `scripts/dev.ps1` 仅在启动后端时读取根 `.env` 的这两个键；前端构建完成后才注入，退出恢复进程原环境。其他启动方式需向后端进程提供同名环境变量。生产部署使用服务器受限环境文件注入，不将凭据写进镜像、源码或小程序包；当前生产是否已配置以 STATE.md 为准。

```powershell
cd F:\zhangwei\AI\Landlord
python scripts/prepare-miniprogram.py
```

用微信开发者工具导入 `F:\zhangwei\AI\Landlord\miniprogram`。本机已定位工具为 `D:\软件\微信web开发者工具\微信开发者工具.exe`，其他机器按实际路径打开。生成器创建被 Git 忽略的 `project.config.json`、`project.private.config.json` 和 `config.local.js`；只将 AppID 和 API 基址写入本地小程序配置，不复制 AppSecret。根目录 `.env` 位于小程序打包目录外。

默认 API 为 `https://www.zoeng.site/landlord/api`。开发配置关闭合法域名校验，备案办理不阻塞开发；真机调试还需按设备环境配置网络/调试选项。进入体验版或发布检查时生成校验开启的配置，并在公众平台完成相应域名条件：

```powershell
python scripts/prepare-miniprogram.py --production
```

生成器保留私有工程配置中的其他字段，仅同步 `setting.urlCheck`，避免私有配置覆盖发布检查。它不替你修改微信公众平台，也不上传或发布代码。

API 基址可换为独立本地实例，例如 `--api-base http://127.0.0.1:18940/api`。模拟器 localhost 指向这台电脑，手机 localhost 指向手机自身；本地地址不作为正式发布配置。

## 账号与文件

- 登录页默认提供租客微信入口，选择“我是房东”后显示现有账号密码表单，不提供小程序注册。租客首次填写入住手机号后创建待关联账号，房东沿用Web核对关联；手填号码不自动认领、复用或合并账号。房东密码只用于本次HTTPS认证，不保存到本地；页面隐藏/切号后清理输入。房东可在工作台或待审核页进入“微信绑定”；仅已审核账号可新绑定，绑定/解绑均验证当前密码。不改原租客身份映射。
- 身份以服务端为准：tenant走本人门户，user/admin走房东业务，待审核房东走独立等待页；跨角色深链重定向至对应页面，不因误入页面销毁有效会话。身份、账单归属和文件权限仍由服务端决定；客户端不传tenant_id获取租客本人资料。
- 房东仅列出active台账，所有业务查询显式携带URL查询参数ledger_id；切台账使旧响应失效，旧请求的401不能清除新台账会话。模块权限不足、无台账和查询失败分别展示状态，管理员没有跨台账特权。
- 账单按服务端 `payable` 展示本期应缴，单列 `total_amount` 与 `carry_in`；逐笔实收、原收据和冲销分别保留，未将各期含结转金额合并成欠费总额。
- 本地保存应用登录令牌及最小账号标识；实收阶段仅对未确认的一笔金额、备注、请求键和对象ID临时保存恢复记录，核对成功、退出/切号或检测到401后清除。业务列表与账单预览不离线缓存。隐藏/离开页面、退出/切号时清空页面数据；旧会话的异步结果不能写回新会话。
- 归档 PDF、上传的 PDF/常见图片通过携带 Bearer 的 `wx.downloadFile` 获取，核对 HTTP 状态和文件头后再打开。下载目标显式放在 `wx.env.USER_DATA_PATH` 下的专用文件名；本轮发现模拟器默认 `http://tmp` 路径无法 unlink，不能用默认临时路径实现退出清理。应用创建的文件在下一次文件打开、退出/切号和下次启动时删除，失败保留索引以重试；原生文件查看器的复制、保存和转发由微信与用户控制。HEIC/HEIF/AVIF 等上传格式的真机兼容尚未验证。

## 房东微信绑定与快捷登录

1. 首次选择“我是房东”，用已有账号密码登录；进入工作台的“微信绑定”，再次输入账号密码并确认绑定当前微信。没有台账不影响管理绑定；待审核账号可看状态/解绑，审核通过后才可新绑定。
2. 下次选择“已绑定微信快捷登录”，只查已有user/admin账号；未绑定提示回到账号密码入口，不注册新房东。此入口不受租客门户开关影响。
3. 同一微信或应用账号已有其他绑定时返回冲突，不覆盖租客或其他房东关系，不按手机号合并账号。当前模型是一条微信身份对应一个应用账号。
4. 解绑需输入当前账号密码；身份删除与AuthVersion递增在同一事务中完成。全部既有应用JWT（含Web与密码登录）失效，当前小程序退出，账号与业务资料保留。APIKey及飞牛网关身份不属于JWT，不因本操作撤销。
5. 每次绑定/快捷登录重新调用wx.login，不复用一次性code。操作失败后不自动重发；可刷新状态后重试。网络丢失时若解绑已在服务端完成，下一次认证会返回401并要求重登。

接口为公开`POST /auth/wechat/landlord-login`（code），已认证`GET /auth/wechat/bind`（只返回bound/current_app/available/status）、`POST /auth/wechat/bind`（password/code）、`DELETE /auth/wechat/bind`（password）。不接收客户端指定user_id/OpenID，不向客户端返回微信身份或session_key。绑定状态与操作均不缓存；密码仅用于当前请求，提交/隐藏/切号后清空。

## 小程序抄表

工作台的“抄表”按所选台账的meters权限显示。具有查看权限即可搜索/分页选择房源、选择账期并读取当前及上期读数；编辑或管理权限可保存水、电、燃气三项读数和可选备注。抄表成员无需取得完整rooms权限，选房接口只返回房号、小区/楼栋与ID，不返回租客联系资料或租金。

- `GET /rental/meter-records/rooms`：10条分页和搜索，范围为当前台账。
- `GET /rental/meter-records/context?room_id=...&period=YYYY-MM`：本期记录、严格早于该账期的最近记录或初始底数、已有账单标记；不把未来记录作为上期。
- `POST /rental/meter-records`：复用原接口，新增可选`expected: {id, updated_at}`；新建传`{id:0}`。同房同月在事务中保存，相同内容重试保持记录ID和版本，旧版本且内容不同返回409。未带expected的原Web调用继续按覆盖语义工作。所有请求都在URL中携带ledger_id。

三项读数必须明确填写非负有限数字，未使用填0。读数低于上期时显示核对提示并使用明确的确认按钮；已有周期计划可能依原收费规则转入人工核对。修改抄表不会重算已出账单；已启用计划的房源补齐抄表后由原分钟调度继续处理，未启用则只保存读数。手工确认出账使用下节独立页面；收费条款或自动计划管理仍在Web。

保存后回查服务器。网络失败/结果不明先禁重复提交并保留输入，用户点“核对服务器记录”：一致即确认；原记录未变化才允许重试；出现其他版本则保留本次输入并显示服务器读数，需明确载入后再修改。页面不自动重发、不保存离线草稿；隐藏、切房/账期/台账或切号会清输入，返回后重新读取。当前有效401会退出，旧页面或旧台账的迟到401不会清当前会话。

## 账单预览与确认出账

工作台按所选台账bills编辑/管理权限显示“预览与出账”，只读成员可通过页面深链预览但不能确认。选择账期、房源及明确入住记录；房源选中后折叠列表。同名租客用记录ID、入住/退租日期区分，同一承租关系的合租成员可多选，不能按姓名合并前后租客。

- `GET /rental/bills/issue-rooms`：bills权限下10条分页/搜索的最小房源列表，不要求rooms权限。
- `GET /rental/bills/issue-tenants?room_id=...&period=YYYY-MM`：当月候选的记录ID、姓名、日期及在租状态，不返回联系电话或完整档案。
- `GET /rental/bills/issue-preview?room_id=...&period=...&tenant_ids=1,2`：只读计算，复用服务端费用、押金、结转与租金日期依据。若本期已有相同/重叠租客或归属待核对的原单，显示原单及详情入口，不新增。旧单缺少冻结租金依据时明确标为按当前档案的计算参考，不改变原单金额。
- `POST /rental/bills/confirm`：仅传`confirmation_token`，URL仍携带ledger_id。签名预览10分钟有效，绑定当前账号、台账、房源、账期、入住ID及显示内容。事务内重新计算并核对；数据变化返回409，重新预览后再明确确认。不会接受客户端租金/费用覆盖，重复确认或已有自动账单返回原单。

缺抄表、低读数、收费条款需人工核对、退租结算及同月前任尚未结算时，本页不给确认令牌并说明Web处理条件。前任已完成结算的同月换租按原结算读数确定后任底数，不覆盖前任账单。本页不包含收款；线下实收使用下节独立页面。收费/自动计划管理及冲销仍在Web。

响应丢失或5xx时禁直接重发，点“核对是否已出账”：存在即查看原单；不存在则读取新的预览，需要再次明确确认。回查失败继续保持待核对。提交期间禁重复与切换；隐藏/换号/换房/月份/台账会清理预览与令牌，不持久化业务草稿或自动重发写请求。

## 线下实收与逐笔收据

账单详情中，bills编辑/管理权限可进入“登记线下实收”。填写实际收到的整笔金额（最多两位小数）和可选备注，先读取最新余额核对，再明确确认；本页不提供在线支付或按收费项目分摊。预收超过应缴时显示核对说明，是否结转抵扣依台账原设置。

复用`POST /rental/bills/:id/pay`，始终传同一笔的request_key及可选`expected:{updated_at,paid_amount,payable}`。已处理的相同请求优先返回原流水，旧版本仍可安全回查；新请求若账单变化返回409，不落款。原Web未带expected保持兼容；流水、收据与累计金额仍在同一事务中写入，PDF失败或生成期间台账权限被撤销会整体回滚。

新增`GET /rental/bills/:id/payment-status?request_key=...`，始终在URL中携带ledger_id，只查指定账单/台账中的原请求。结果不明或失败先核对；未找到不等于确定失败，只能按原金额、备注及请求键明确重试，不自动发送。有待核对记录时禁止另开一笔，工作台提供恢复入口。

为了普通关闭后恢复，提交前临时保存**未确认的一笔**金额、备注、请求键、账号/账单/台账ID；不保存额外登录凭据、租客姓名或联系方式。页面隐藏清渲染数据但保留恢复记录，核对成功、退出/切号或检测到401后删除。退出后若仍需核对实收，重新登录先核对服务器逐笔流水，不将退出当作撤销收款。

账单详情与实收页的每笔“查看原始收据/冲销凭证”通过固定`/rental/documents/:id/file?ledger_id=...`、Bearer鉴权下载，校验PDF头后调用原生openDocument；bills查看权限即可读取，无需完整payments权限。未归档的历史流水明确说明缺少PDF，不伪造原件。文件跟踪清理沿用上节，迟到401不清新台账/会话。冲销、退款核对及按项目分摊仍在Web。
