## 合同与收据

在「租户管理 → 合同 → 合同 PDF」生成和查看归档原件；续租协议需选择对应续租记录。管理员在「系统配置 → 平台合同模板」维护正文，每次保存创建新版本。原件不随档案修改或模板升级改变，生成的是待签署打印稿，签署件通过原有附件入口上传。

在账单登记线下实收后自动生成本次收据，在账单详情或收款记录查看；填原因可整笔冲销，原流水与原 PDF 保留，新增负数流水和冲销凭证。当前账单的打印入口统一显示应缴通知单，逐笔收据读取归档文件。旧流水不会自动伪造历史 PDF。

PDF 和数据快照分别存入 SQLite，现有数据库备份可一起保存；下载会校验文件指纹。Windows 自动查找 Edge/Chrome，也可设置 `LANDLORD_PDF_BROWSER` 为浏览器可执行文件路径。Linux 镜像的 Chromium Headless Shell 与 Noto CJK 已实测，HOME/XDG 位于单次转换临时目录，兼容只读容器；转换器不可用时收款/冲销整体不落库，恢复后用原表单重试。同一实例串行转换 PDF，含排队最长等待 20 秒。

## 周期任务与提醒

房东在「周期任务」按房源和明确的承租关系建立计划。默认沿用缴费日，抄表和出账提前 3 天（最早当月 1 日），再提前 3 天提醒；日期可调整，范围为 1–28 日。所有日期以香港时间 08:00 为起点，每分钟检查，启动后补偿停机期间的到期任务。

当期缺抄表时等待，补录后自动继续；多个欠缺账期按先后处理。重复检查复用原账单，租约或费用条款改变时需要重新保存确认；现有租客需房东主动启用计划。抄表待办发给有权限的房东成员，新账单只通知绑定的对应租客。

在「消息与推送」查看站内消息、标记已读、开启/关闭本设备通知和发送测试通知。Safari 请先通过分享菜单「添加到主屏幕」，从桌面图标打开后点「开启此设备通知」。系统推送需要 HTTPS 和用户授权；服务返回接收成功不代表手机已显示。锁屏通知只提示有新消息，详情需登录查看。退出账号会解除本设备推送；离线仅显示重连页，不缓存业务 API 或 PDF。

后续构建使用 [GitHub Actions](https://github.com/zwdotnet/Landlord/actions)，步骤与制品说明见 [GitHub 云端构建](doc/GitHub云端构建.md)。GitHub 托管 runner 构建前端与 Linux 镜像，保存可部署制品，发布仍单独执行。`deploy/build-image.sh` 保留为独立 Linux 构建机的备用入口，要求至少有 3 GiB 可用内存。生产 VPS 已设置 4 GiB swap，仅接收制品并运行服务。

## 备份恢复与上传边界

管理页及每日03:00的`.db`快照只覆盖数据库记录和服务端生成的归档PDF；上传合同、身份证合成图/照片、抄表/房源/物品照片在磁盘目录内，不能靠`.db`独立恢复。完整恢复使用[scripts/full-backup.py](scripts/full-backup.py)：先停止对应实例的所有写入者，再对其data目录创建校验归档；工具不会替你停服务，也不保证运行中数据库与文件的一致性。

```powershell
python scripts/full-backup.py create --offline --data-dir D:/Landlord/data --output D:/Landlord-backups/full-20261115.zip --config-file D:/Landlord/bootstrap.env
python scripts/full-backup.py verify D:/Landlord-backups/full-20261115.zip
python scripts/full-backup.py restore D:/Landlord-backups/full-20261115.zip --destination D:/Landlord-recovery-20261115
```

示例路径须换成目标隔离/维护实例，不能对当前预览或生产盲目运行。归档包含一致性`data/db/rental.db`、data下其他文件（排除旧backups和主库WAL/SHM），以及显式指定的配置文件；清单保存相对路径、大小、SHA256。只接受默认布局中的主库；自定义外置DB_PATH、UPLOAD_DIR、外部密钥或代理配置须单独纳入并验证，不能宣称该归档自动包含机器其他目录。恢复只允许新目标目录，输出`data/`和`config/`，不覆盖后来业务；核对鉴权文件和账款后才能切应用路径。SHA用于完整性校验，不证明来源可信；归档含敏感资料，应限制权限并按运营要求加密保存。

创建、校验与恢复还会核对数据库引用的上传合同、各类照片及待审核照片是否真实存在；缺件或路径无效会拒绝，即使归档清单与剩余文件一致也不能通过。遇到缺件先保留原实例和证据，在隔离副本核查来源，不通过删除业务引用强行制造成功备份。

Linux维护用户须有足够的数据目录及WAL辅助文件权限；只读SQLite连接也可能需要初始化辅助元数据。停写后用具备权限的维护身份执行，不能为备份方便放宽生产目录权限。完整备份的暂存与解包应放到容量足够的维护磁盘；它在应用容器之外运行，不把256MiB应用tmpfs视为通用完整备份空间。本次约30MiB合成数据的宿主维护临时盘采样峰值约62.1MiB，仅供核对该样本。

完整备份建议每天一次并在升级前额外执行，至少保留7个按日期独立的副本及一份受限异地副本；这是维护方案，本轮没有创建计划任务或生产异地副本。若每天确实成功完成一次，最大预期数据丢失窗口约24小时；本机合成恢复耗时见审查报告修复节，不能当作生产RTO承诺。日常`.db`快照继续使用原保留设置。

业务multipart请求整批最多32MiB，单文件仍20MiB，文字字段合计64KiB；CSV导入单文件8MiB/请求9MiB，OCR图片10MiB/请求11MiB，备份上传沿用256MiB上限。所有上传解析/持久化在单进程内共享一个名额，同时上传返回503，请确认本次未接收后稍后再试；超总量返回413。附件、合同、房源/物品/抄表照片整批预检后事务保存，存储或数据库失败清理本批文件；响应不明时刷新列表核对，不自动重传。进程被强制终止仍可能留下无记录的磁盘文件，维护时按清单核对，不能据此删除真实附件。

直连默认不信任`X-Forwarded-For`/`X-Real-IP`。反向代理须按应用实际来源设置`TRUSTED_PROXIES`或`-trusted-proxies`（精确IP/CIDR，逗号分隔），不要盲目写127.0.0.1、整个私网或0.0.0.0/0；容器常看到桥接网关。fnOS socket身份仍走原可信标记。11月16日部署实测Caddy来源172.19.0.1并精确配置172.19.0.1/32，原环境值及0600保持；网络重建后须重核。不同客户端分桶已有隔离TCP证据，未在生产施加限流压力。

上游 `scripts/test-all.sh` 和打包脚本仍保留历史路径、上游发布渠道与镜像配置，尚未作为 Landlord 的发布入口。当前使用 GitHub Actions 制品保存镜像与匹配的只读前端，没有向公共容器仓库推送镜像。
