## 工程决定

1. 以 rental v0.7.1 为起点，保留 MIT 许可证，固定上游提交 `98e65d2c65c04a8e6bba321b6774ded72c5e812d`。不把上游原始结论当作本项目的验证结果。
2. 继续使用 Go / Gin / GORM / SQLite、Vue 3 / TypeScript。小范围使用先保持单体应用，不增加 Redis、微服务或支付网关。
3. 房东个人台账与授权的共同台账沿用上游模型。租客不拥有房东业务写权限；平台管理员管理账号与运行状态，不因管理员身份自动获得其他房东台账的业务数据。当前管理员与房东共用 Web 布局，管理员额外显示系统管理菜单，尚无独立管理员首页。租客账号与租户档案当前一对一关联；平台运维拥有整库备份权限，业务接口仍按台账授权。独立管理员控制台、多租约切换不属于本轮已确认实现范围。
4. 第一阶段暂以现有 Tenant 档案表示一次入住关系；续租记录增加生效日。账单保存明确的租客 ID 集合与租客集合键，姓名仅作展示。正式合同版本、完整条款和文件快照在第二阶段补齐，不把当前租客档案冒充不可变合同。
5. 同一房间同一月份允许不同入住关系各有账单；同一租客集合禁止重复生成。押金、固定费周期与结转按租客集合分开。共同承租的一张账单可明确归属于多个租客，房租不按人数叠加；成员变更后应核对押金和首账，不自动转移原租约余额。
6. 老账单不按姓名、房号或月份自动授予租客。迁移只增加字段和调整唯一索引，保留原金额；房东在账单详情手动确认历史账单归属后，租客才可见。已确认归属不可通过此入口再次分配。
7. 续租日期按闭区间：新起日是原到期日的次日；已过期则从登记当天开始。租金以续租生效日分段，不立即覆盖房源默认租金，已开账单保留原快照。
8. 租金按自然月实际天数累计，并在本期合计时统一保留两位小数：每日租金 = 当日适用月租金 / 当月实际天数。包含入住日、退租日和合同到期日；有明确租期时只计算租期内的天数。多月预付仍沿用 rental 的自然月账期，不引入按入住日滚动的周年账期。
9. 月中调租可按日期分段折算；共同承租人的租金条款冲突，或上游旧续租记录缺少生效日时，转人工核对。本期租金可由房东明确覆盖；水电和其他固定费不套用租金按天折算规则。
10. 账单使用当期独立抄表记录。前期读数只取目标账期以前的资料，同账期优先沿用已开账单快照，防止未来读数和过期台账覆盖结算读数。日期明确的同月换租承接前任已开结算单的末读数；缺少交接抄表资料时需房东补齐和核对。
11. M1 的累计实收打印视图在 M2 中统一改为当前应缴通知。逐笔收款通过专门登记入口生成不可变 PDF 收据；冲销新增负数流水与凭证，原收款仅标记已冲销，不改写原金额和原 PDF。旧流水保留，不伪造历史 PDF。
12. M2 合同模板采用只能新增的版本，归档凭证同时保存独立的条款/业务快照与 PDF 二进制及 SHA-256；二者均放入 SQLite，数据库备份包含原件。重印读取原文件。Linux 镜像使用 Chromium Headless Shell，Windows 开发使用本机 Edge/Chrome，生成中文 A4 PDF；签署状态仍通过签署件附件管理，电子签约尚未接入。
13. 收款、收据、余额、结转在同一事务写入；PDF 转换失败、重复请求或生成期间账单被修改，均不能留下半笔登记。已有归档凭证的账单禁止 CSV 覆盖与删除；有关房源、租客的删除和跨台账移动也受保护。
14. 定时出账、抄表任务采用 SQLite 持久化任务、唯一业务键、可重试和启动补偿，香港时间 08:00 起每分钟检查。缺抄表等待，历史账期按顺序补偿；房东主动启用，当前条款变化需再次确认；租期结束后不再出账。自动出账与站内消息事务一致，Web Push 经独立持久化队列投递。
15. PWA 使用相对 scope，适配 `/landlord/`；仅缓存离线页与图标，账号切换隔离通知，更新由用户确认。VAPID 身份保存于数据库；通知服务接收与手机实际送达分别记录。Safari 需添加到主屏幕后主动授权。小程序复用同一套受保护 API。
16. 目标路径为 `https://www.zoeng.site/landlord/`，apex 按现有配置跳转到 www；保留主页及所有既有子站。生产 VPS 只接收、校验和运行制品，使用 GitHub 托管 runner 构建，NAS 可用于隔离验证；18:58 的 NAS 构建属于历史。用户2026-11-11授权的 swap、构建和部署已完成；后续动作遵循当前用户指令。
17. 用户选择 Headless Shell 后，2026-11-11 22:10 已部署源码5323d74；PDF 排队与转换总超时为20秒，低于 HTTP 30秒写限额，维持串行与512MiB生产内存限额。性能与验证的观察时间、范围见 [上线报告](HeadlessShell上线与资源验证-20261111.md)，不以独立渲染器样本代替完整服务占用。

### 可复用的业务与权限

公网 API 基址候选为 `https://www.zoeng.site/landlord/api`，保留 `/landlord/` 子路径；代码内部挂载 `/api`。小程序必须请求完整 HTTPS URL。

| 能力 | 现有接口（相对 API 基址） | owning source |
|---|---|---|
| 小程序微信登录 | `POST /auth/wechat/login`，首次缺联系手机返回 phone_required，成功返回应用 token 与 user | `server/user/wechat.go`、`miniprogram/pages/login/` |
| Web 账号密码登录 | `POST /auth/login`，返回 token 与 user | `server/user/handler.go`、`server/user/service.go` |
| 当前账号与关联状态 | `GET /auth/me`、`GET /rental/portal/status` | `server/user/handler.go`、`server/rental/tenant_portal.go` |
| 本人资料、账单与实收 | `GET /rental/portal/profile`、`/bills`、`/bills/:id`、`/payments` | `server/rental/tenant_portal.go` |
| 上传合同与文件 | `GET /rental/portal/contracts`、`/contracts/:id/file` | `server/rental/tenant_portal.go` |
| 归档新签/续签与凭证 PDF | `GET /rental/portal/agreements`、`/documents/:id/file` | `server/rental/issued_documents.go` |

`Authorization: Bearer <应用 JWT>` 可由现有中间件认证。接口按服务端账号角色、状态、AuthVersion 和已关联租客档案认人；客户端不按姓名、手机号、房号或自报 tenant_id 获得业务权限。租客注册受注册/门户配置约束，注册后待关联，房东显式关联才激活；初始化管理员保持部署者私有入口，不放进小程序。

源码中的租客门户、账单归属与凭证隔离测试可作为后续定点回归入口：`tenant_portal_test.go`、`tenant_portal_scope_test.go`、`issued_documents_test.go`。微信登录测试为 `server/user/wechat_test.go`；实际已运行范围和回执见 STATE.md，文档整理不自动触发测试。

### 客户端与登录适配

1. 首版延续 M5 的租客查询范围：登录/待关联、本人房屋与资料、合同、账单明细、逐笔实收与原件。房东操作、在线支付和微信订阅消息按后续范围安排；现有 PWA Web Push 不能直接当作小程序订阅消息。
2. 首版采用原生微信小程序（JavaScript/WXML/WXSS），无客户端 npm 依赖，底部入口提供普通/选中图标，独立实现界面与网络/文件适配；复用 API 契约和业务规则，现有 Vue DOM、路由和 Blob 预览不直接迁入。入口为 `miniprogram/`，根 app.json 仍是上游打包元数据。
3. 小程序移除账密注册和登录，改用微信登录。首次填写入住手机号，号码仅作联系资料；房东沿用 Web 租户管理确认账号关联，之后微信直接登录。手填号码不自动认领档案或合并相同手机号的旧账号；Web 账号入口及原有权限规则保留。
4. 微信身份链路为 wx.login → 后端 code2Session → 按 (AppID, OpenID) 唯一映射租客账号 → 应用 JWT。AppSecret 只在后端进程环境，session_key 不返回或写入客户端。首次账号固定为待关联租客，不能创建管理员或房东；停用、解绑及门户权限继续由现有服务端规则执行。真实平台与物理设备验证结果分开记录于 STATE.md。
5. PDF 实现为 `wx.downloadFile` 携带 Authorization → 检查 HTTP 状态和文件头 → `wx.openDocument` 打开本地 PDF；常见上传图片走预览器。下载回调 success 不保证是 200，401/403/404 或 JSON 错误不能交给预览器。服务端原件已有 PDF 类型、SHA 校验与 no-store；客户端将下载目标放在可自行删除的 USER_DATA_PATH，记录文件索引并在退出/切号、下次打开和启动时清理，不能把 no-store 当作本地文件自动清理保证。真实微信基础库与手机显示/打印仍需验收；模拟器默认临时目录无法删除的失败事实及最终复验见 STATE.md。
6. 若考虑 web-view 承载现有网页，还需单独核对主体资格与业务域名；公开文档镜像说明个人类型受限，不能假设所有账号都支持。首版不以此作为确定方案。

### 平台接入与发布条件

- **账号与主体**：确认小程序已注册、主体类型、AppID、管理员/开发者与体验者权限；在该账号后台确认可选类目及需要的资质，发布前完成小程序备案及后台要求的认证/审核。小程序备案与 API 域名的 ICP 备案是分别核对的项目。
- **域名与开发阶段**：本地开发可使用开发者工具“不校验合法域名”等调试豁免，不以备案完成作为开发前置条件。体验版与正式发布阶段再核对实际账号要求：微信官方开发指引列明 HTTPS、预配置通信域名、域名 ICP 备案；`request` 与 `downloadFile` 合法域名候选均为 `https://www.zoeng.site`，不是带 `/landlord/api` 路径的 URL。查询首版不必为不存在的上传/长连接功能配置额外域名。证书信任、协议、域名后台接受情况及境内手机连通性需另验；开发调试豁免不代表发布检查已通过。
- **隐私与审核材料**：依实际读取的租客资料、合同及文件能力填写后台隐私保护指引，提供审核可用的隔离演示账号/操作说明；不将真实租客资料放进审核样例。是否要求特定类目资质与配置，以所选主体后台为准。
- **工具与真机**：确定微信开发者工具安装路径、登录与项目权限；用真实 AppID 验证开发环境，开发阶段可保留域名调试豁免。进入体验/发布验收时关闭“不校验合法域名”等豁免，验证 iPhone/Android 的登录、待关联、跨账号隔离、合同/收据打开及退出清理；开发调试结果与体验版、发布条件分别记录。
