## iPhone 开始前

1. 让 iPhone 与电脑连接同一局域网。用 Safari 打开 `http://192.168.124.10:19024/api/health`，确认返回 JSON 且 `data.status` 为 `ok`。用户已回报本轮实际 iPhone 此项通过；机型、iOS 及微信版本留待正式验收补记，电脑自测不替代手机观察。
2. 如果打不开，先确认电脑 IP、电脑未休眠、演示服务运行且网络不是访客隔离网络。当前 Windows 会话非管理员，未修改防火墙；需要入站放行时，在管理员 PowerShell 执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File F:\zhangwei\AI\Landlord\.runtime\iphone-ready-20261114-01\Enable-Lan.ps1
   ```

   脚本只添加名为 `Landlord-iPhone-Demo-19024-20261114` 的规则，限 Private 网络、指定演示程序、TCP 19024、本机 `192.168.124.10` 与远端 `192.168.124.0/24`。本轮手机入口已连通，无需执行；当前防火墙未改。若后续网络变化而实际执行，结束后可由管理员运行 `Remove-NetFirewallRule -Name Landlord-iPhone-Demo-19024-20261114` 删除该条规则。
3. 查看本机账号卡，再使用当前 AppID 的开发者/体验成员微信扫描 [开发预览二维码](../.runtime/iphone-ready-20261114-01/raw/preview-qr.jpg)。这是临时开发预览。若微信提示本地网络权限，请允许；若提示域名校验或 HTTP 限制，记录原提示并检查开发预览的调试开关，必要时使用开发工具“真机调试”。这些手机侧条件尚未观测，不凭项目里的 `urlCheck:false` 宣称已经满足。
4. 确认打开的是本次合成环境再开始业务。页面错误应记录操作、提示和房号；不将密码、登录 code、令牌或微信身份放进截图/报告。

同一 AppID 下，一个微信身份只能对应一个应用账号。先测房东微信绑定/快捷登录，完成后用密码确认解绑，再测租客首次微信登录；解绑使原房东全部应用 JWT 失效，需要重新登录。也可分用两个微信账号，但不能覆盖已有身份来省略流程。
